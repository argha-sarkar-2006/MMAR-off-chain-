3rd-Route / MMAR Documentation

Welcome to the official developer guide for 3rd-Route (Multimodal Multi-Agent Workbench), a sovereign, off-chain artificial intelligence routing platform.

3rd-Route routes and coordinates multi-stage tasks across:

  • Vision Stage: Reads architectural diagrams, UMLs, charts, and error screenshots with OCR and neural vision models.
  • Reasoning Stage: Performs local RAG against ingested documents and conducts real-time web search for technical verification.
  • Coding Stage: Generates tested, working code from technical specifications using Ollama Cloud or local models.
  • Autonomous Router: Automatically inspects user intent, classifies query types, and manages pipeline execution flow.
Key Sovereign Advantage: 3rd-Route runs locally on your computer. Your conversations, document chunks, and embeddings never leave your machine unless routed explicitly to the AI inference APIs you configure.

System Prerequisites

Ensure your workstation meets the following runtime requirements before running 3rd-Route:

  • Python 3.10 or higher: Required for the core orchestrator and FastAPI bridge.
  • Node.js 18+ & npm: Required for building the React frontend if running from source.
  • Tesseract OCR: Required for local OCR text extraction from images and diagrams.

Installing Tesseract OCR

bash 
# Ubuntu / Debian
sudo apt-get update && sudo apt-get install -y tesseract-ocr

# macOS (Homebrew)
brew install tesseract

# Windows
# Download installer from official UB-Mannheim repository and add to PATH:
# C:\Program Files\Tesseract-OCR

Quickstart Setup

Follow these steps to set up the development environment from source:

1. Clone Repository & Virtual Environment

bash 
git clone https://github.com/argha-sarkar-2006/MMAR-off-chain-.git
cd MMAR-off-chain-

# Create virtual environment
python -m venv .venv

# Activate on Windows (PowerShell)
.venv\Scripts\Activate.ps1

# Activate on Linux / macOS
source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt

2. Configure Environment Variables

Copy the example environment configuration and supply your API keys:

bash 
cp .env.example .env
env 
# Primary model credentials
OPENROUTER_API_KEY=your_openrouter_api_key_here
OPENROUTER_API_KEY_ALT=optional_alternate_key
OLLAMA_API_KEY=your_ollama_cloud_key_here

# Optional: Local Ollama endpoint
OLLAMA_HOST=http://localhost:11434

Release & Local Distribution

3rd-Route is distributed as a self-contained local application release package. Users do not need complex cloud accounts:

  1. Download the latest release archive (3rd-Route-v1.0.0.zip) from GitHub Releases.
  2. Extract the archive into your preferred folder on Windows, macOS, or Linux.
  3. Configure your .env file with your OpenRouter and Ollama keys.
  4. Start the local server and client workbench.
powershell 
# Terminal 1: Start Backend API
python server.py

# Terminal 2: Start Frontend Workbench
cd frontend
npm install
npm run dev

1. Router Engine (modelrouter.py)

The central coordinator orchestrates requests. When a prompt arrives:

  • Image Inspection: If an image is attached, the Vision stage is triggered first.
  • Intent Classification: Classifies whether the task requires web research, knowledge base retrieval, or code synthesis.
  • Context Threading: Feeds the structured output of earlier stages directly into downstream modules.

2. Vision Stage (vision.py)

The vision engine handles visual comprehension:

  • Uses Tesseract OCR to extract textual labels, error stacks, and system names directly.
  • Invokes Google Gemini Flash as the primary vision model for architectural reasoning.
  • Features automatic 503 / 429 failover to OpenRouter vision models if primary inference is throttled.

3. Reasoning & Web RAG (reasoning.py)

The reasoning stage synthesizes facts before coding begins:

  • Queries local knowledge.db for matching documents using SQLite FTS5 BM25 scoring.
  • Executes web search plugins via OpenRouter to retrieve latest SDK documentation and real-world patterns.
  • Generates a clean, unambiguous technical specification for the coding model.

4. Coding Stage (coding.py)

The coding stage executes pure software implementation:

  • Connects to Ollama Cloud models (such as gpt-oss:20b) or local Ollama instances.
  • Accepts structured inputs from the reasoning stage to write idiomatic, bug-free, fully typed source code.
  • Appends execution instructions, unit tests, and runtime requirements.

SQLite FTS5 Knowledge Base

Rather than relying on heavy vector database servers, 3rd-Route uses SQLite with the FTS5 (Full-Text Search) extension:

python 
# Ingesting a document into local knowledge base
python knowledge.py --ingest "path/to/spec.pdf"

# Querying the knowledge base directly
python knowledge.py --query "How does the caching tier work?"
Performance Note: SQLite FTS5 queries execute in sub-millisecond timeframes, require 0 megabytes of extra background memory, and can be backed up as a single file: knowledge.db.

Document Ingestion Pipeline

Ingesting reference material into 3rd-Route creates a private, isolated corpus. The system parses multi-format documents, splits them into semantic paragraphs, computes deterministic content hashes to prevent duplicates, and populates the SQLite FTS5 virtual index:

  • Supported File Formats: PDF (.pdf), Markdown (.md), Plain Text (.txt), JSON, and source code files.
  • Deduplication: SHA-256 content hashing skips redundant re-ingestion of unmodified files.
  • Account Isolation: When Auth0 is enabled, files are automatically assigned to the authenticated user's isolated database namespace.
bash 
# Ingesting multiple files via CLI
python knowledge.py --ingest "docs/architecture.pdf"
python knowledge.py --ingest "README.md"

# Checking ingested documents in database
python knowledge.py --list

FastAPI Web Server (server.py)

The backend API bridges the React workbench to the underlying Python pipelines:

text 
POST /api/chat          - Submit multimodal query and stream pipeline results
GET  /api/health        - Verify backend readiness and active models
POST /api/knowledge     - Ingest document (PDF, TXT, MD) into isolated account DB
GET  /api/models        - Fetch available model options and routing modes

Auth0 & Session Isolation

3rd-Route includes integrated Auth0 authentication support for multi-user workstations:

  • Configure Auth0 credentials directly in frontend/.env.local or through the in-app Setup modal.
  • Each authenticated user account receives an isolated chat history and private knowledge space.
  • Optional guest mode allows instant offline development without an Auth0 account.

CLI & Headless Mode

Run 3rd-Route in headless automation scripts or interactive terminal sessions:

bash 
# 1. Interactive terminal loop
python modelrouter.py

# 2. Single text query
python modelrouter.py --text "Explain how vector databases work."

# 3. Vision + prompt analysis
python modelrouter.py --image "diagram.png" --prompt "Explain this architecture"

Configuration Reference (config.py)

All configuration parameters are centrally validated:

python 
# Available configuration variables in config.py
OPENROUTER_API_KEY      # API key for OpenRouter inference
OLLAMA_API_KEY          # API key for Ollama Cloud
DEFAULT_VISION_MODEL    # google/gemini-2.0-flash-exp:free or similar
DEFAULT_CODING_MODEL    # gpt-oss:20b
MAX_RETRIES             # Fallback retry count (default: 3)
REQUEST_TIMEOUT         # Timeout in seconds (default: 45)
